# Ход выполнения практической работы № 6

## 1. Анализ исходного проекта

Изучены `index.html`, файлы в `css/`, `js/app.js` и тесты. Исходный стенд содержал конфликты каскада CSS, глобальные селекторы подрядчика, некорректные состояния полей, проблемы с клавиатурным управлением, модальным окном и переполнением экрана на узких устройствах. Результаты первоначальной диагностики зафиксированы в `reports/AUDIT_TEMPLATE.md` и `reports/baseline-npm-test.txt`.

## 2. Исправление архитектуры стилей

Стили распределены по слоям, разделены токены оформления и стили компонентов. Внешний виджет ограничен собственной областью. Состояния danger и другие модификаторы привязаны к конкретным семействам компонентов, а не к глобальному классу. Убраны конфликтующие селекторы, дубли и ограничения минимальной ширины, вызывавшие горизонтальную прокрутку.

## 3. Поведение и доступность

Для полей исправлен момент отображения ошибки; для фокуса используется `:focus-visible`. Переключатель доступен с клавиатуры. Диалог открывается через `showModal()`, закрывается клавишей Escape и возвращает фокус к кнопке запуска. Предусмотрены светлая и тёмная темы и режим уменьшения движения.

## 4. Проверка результата

Структурные тесты: `npm test` — 18 из 18 пройдены в текущем архиве. В приложенном ранее журнале браузерных тестов — 11 из 11, матрица из 48 сценариев — 48 OK. Эти показатели браузерной проверки взяты из материалов архива; в текущей среде браузерный прогон повторно не выполнялся.

Проверенные ширины по отчёту: 320, 375, 768, 1024, 1440 и 1920 px в двух темах. Скриншоты размещены в `reports/screenshots/`.

## 5. Стресс-тест

Выполнен конверт C: кнопка действия внутри карточки занимает всю ширину, если ширина контейнера не превышает 400 px. В остальных случаях она сохраняет естественный размер. Правило не затрагивает кнопки вне карточек. Доказательства: `reports/STRESS_C.diff`, `reports/stress-c.txt` и `tests/browser/quality.spec.js`.

## 6. Запуск и демонстрация

Открыть папку `project` в VS Code, в терминале выполнить `npm install` (если зависимости отсутствуют), затем `npm run dev`; перейти на `http://127.0.0.1:5173`. Для структурной проверки выполнить `npm test`, для браузерной — `npm run test:e2e` при установленном браузере Playwright.

## 7. Материалы сдачи

Исходники приложения, DOCX-отчёт, аудит, ADR, матрица сценариев, регрессионный отчёт, результаты тестов и скриншоты находятся в папке проекта. Подробные пояснения см. в `reports/` и в основном `README.md`.
